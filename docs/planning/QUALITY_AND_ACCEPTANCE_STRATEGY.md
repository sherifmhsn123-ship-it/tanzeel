## 1. فلسفة الجودة

1. **مخاطر قبل تغطية:** نختبر ما يمكن أن يفقد بيانات أو يضر أمانًا أو يكسر تجربة، لا نطارد نسبة تغطية.
2. **الفشل أولًا:** كل ميزة تُختبر في مسارها الفاشل، لا الناجح فقط.
3. **حتمية:** لا شبكة حقيقية، ولا انتظار زمني حقيقي، ولا ترتيب غير محدد.
4. **عزل:** كل اختبار يستخدم مجلدًا مؤقتًا، قاعدة مؤقتة، وساعة/مهلة قابلة للحقن.
5. **أدلة لا انطباعات:** الأمر، البيئة، الناتج، والتاريخ.
6. **لا إخفاء:** الاختبار الفاشل يُذكر؛ لا يُعطّل بصمت، ولا يُعاد تشغيله حتى ينجح بلا تفسير.
7. **العربية ليست اختبارًا تجميليًا:** RTL، النص الطويل، الجمع، الأرقام، والتواريخ ضمن القبول.
8. **الأمان جزء من الجودة:** لا يُؤجل إلى مرحلة 11.
9. **الاستعادة جزء من السلوك:** إعادة التشغيل والانقطاع ليست حالات نادرة.
10. **كل مرحلة لها بوابة:** لا انتقال بالكلام.

## 3. ما يُختبر في كل ميزة

كل PR لميزة يجب أن يغطي، حيث ينطبق:

- الحالة الناجحة الأساسية.
- مدخلات فارغة/طويلة/عربية/غريبة/غير صالحة.
- فشل شبكة/مهلة/انقطاع/إعادة محاولة.
- إلغاء في منتصف العمل.
- فشل جزئي (عنصر واحد في قائمة/جزء واحد).
- إعادة تشغيل أو استعادة.
- تعارض ملف/مسار/اسم.
- صلاحيات/قرص ممتلئ/مسار مقفل.
- حدود الحجم/العدد/الزمن/الاتصالات.
- حقن/SSRF/مسار خبيث/رسالة مزيفة.
- RTL/LTR ونص طويل إن كان هناك واجهة.
- رسالة خطأ مفهومة وخطوة تالية.
- عدم كسر سلوك قائم (regression).

**ممنوع:** اختبار ينجح فقط لأن الشبكة متاحة، أو لأن الملف موجود مسبقًا، أو لأن الترتيب صدفة.

## 4. قواعد كتابة الاختبارات

1. اسم الاختبار يصف السلوك، لا اسم الدالة فقط.
2. Arrange/Act/Assert واضح.
3. لا `sleep` حقيقي؛ استخدم ساعة/مهلة وهمية.
4. لا تعتمد على `localhost` شبكي حقيقي؛ استخدم خادمًا داخل العملية أو mock transport.
5. لا ملفات في مجلد المشروع؛ `tempdir`.
6. لا أسرار/بيانات شخصية في fixtures.
7. كل fixture موثقة المصدر، وصغيرة، ومرخّصة.
8. لا assertions هشة على نصوص تقنية كاملة؛ استخدم رموزًا/رسائل مترجمة.
9. لا تجاهل اختبار بلا Issue وسبب وتاريخ.
10. لا retry تلقائي يخفي flakiness؛ العيب يُصلح.
11. اختبارات الأمان تُكتب كاختبارات سلبية صريحة.
12. اختبارات الاستعادة تحاكي إنهاءً/انقطاعًا، لا تعتمد على إغلاق نظيف فقط.
13. اختبارات التثبيت لا تُستبدل ببناء ناجح.
14. لا تُقاس الجودة بعدد الاختبارات وحدها.

## 6. بوابة PR

كل PR يجب أن يمر:

- [ ] Issue مرتبط، وPR صغير يفعل شيئًا واحدًا.
- [ ] البرومبت الحرفي في الوصف.
- [ ] اختبارات الميزة + حالات الفشل في نفس PR.
- [ ] `lint` و`typecheck` و`test` و`build`.
- [ ] `cargo fmt --check` و`clippy -D warnings` و`cargo test`.
- [ ] CI على Windows وLinux وmacOS.
- [ ] فحص أسرار نظيف.
- [ ] لا اعتماد جديد غير مبرر/مرخّص.
- [ ] RTL/LTR إن كان تغيير واجهة.
- [ ] وثائق محدثة، وما لم يُختبر موسوم.
- [ ] خطة تراجع إن كان خطرًا.
- [ ] مراجعة بشرية.

**لا يُقبل:** «الاختبارات ستعمل لاحقًا»، أو «اختبرته محليًا» بلا أمر/نتيجة، أو تعطيل فحص.

## 7. بوابة المرحلة

المرحلة لا تُغلق إلا بـ:

1. **نطاق مكتمل:** كل بند مطلوب منفذ أو مؤجل بقرار مالك مكتوب.
2. **اختبارات آلية:** كل اختبارات المرحلة تنجح على الأنظمة الثلاثة.
3. **اختبارات يدوية:** كل بنود القبول اليدوي موثقة.
4. **حالات فشل:** مغطاة أو معلنة كخطر مقبول.
5. **أمان:** threat model محدث، ولا ثغرة حرجة جديدة.
6. **أداء:** أهداف المرحلة مقاسة أو معلنة **لم تُختبر** مع سبب.
7. **وثائق:** محدثة، والحالات غير المختبرة موسومة.
8. **مراجعة:** مالك/مراجع بشري.
9. **دليل:** حزمة قابلة لإعادة الإنتاج.
10. **قرار:** اعتماد صريح للانتقال.

## 11. مصفوفة اختبار المرحلة 13

### 11.1 الوظائف

- بدء، إضافة مهمة، تحليل، اختيار، تنزيل، إيقاف، استئناف، إلغاء، إعادة محاولة.
- طابور، أولوية، حدود، جدولة، سجل، حذف سجل، فتح ملف/مجلد.
- فيديو واحد، قائمة، صوت، ترجمة، دمج.
- سحب صفحة، معاينة، تأكيد.
- التقاط من متصفح، تأكيد.
- إعدادات، لغة، مظهر، مجلد.

### 11.2 البيانات والاستعادة

- انقطاع شبكة، إعادة اتصال.
- إغلاق التطبيق أثناء تنزيل.
- إنهاء العملية قسرًا.
- إعادة تشغيل Windows.
- قاعدة بيانات مقفلة/تالفة.
- ملف مؤقت يتيم/ناقص.
- ملف نهائي موجود/مقفل.
- قرص ممتلئ/صلاحية.
- أسماء عربية/Unicode/محجوزة/طويلة.

### 11.3 الأمان

- رابط `file:`, `javascript:`, `data:`.
- `localhost`, `127.0.0.1`, `::1`, IP خاصة، تحويل إلى خاص.
- مسار `..`، مسار مطلق خبيث، symlink/reparse.
- رسالة متصفح مزيفة/كبيرة/بحقول إضافية.
- توقيع تحديث خاطئ.
- سر في سجل/حزمة تشخيص.
- صلاحيات مثبّت.

### 11.4 الأداء

- بدء بارد/دافئ.
- ذاكرة خمول وتحت تنزيلات.
- CPU أثناء التقدم.
- 3 تنزيلات متزامنة، ملف كبير، قائمة صغيرة.
- تجميد الواجهة.
- استهلاك سجل.

### 11.5 الواجهة والوصول

- RTL/LTR لكل شاشة.
- نص عربي طويل، أرقام، تواريخ.
- لوحة مفاتيح فقط.
- قارئ شاشة.
- تباين.
- نافذة ضيقة/خط كبير.
- حالات فارغة/تحميل/خطأ/تأكيد.
- إشعارات/tray.

### 11.6 التثبيت والإصدار

- تثبيت نظيف Win10/11.
- ترقية من نسخة سابقة.
- تراجع.
- إلغاء تثبيت مع/بدون حذف الملفات.
- إزالة Native Messaging.
- تشغيل بلا admin.
- تحديث صالح/خاطئ.
- checksums/SBOM.

## 18. الخلاصة

الجودة في Tanzeel تعني:

1. سلوكًا محددًا.
2. اختبارًا يعيد إنتاجه.
3. دليلًا موثقًا.
4. حالات فشل مغطاة.
5. أمانًا وخصوصية.
6. مراجعة بشرية.
7. اعتمادًا صريحًا.

أي شيء أقل يبقى `IMPLEMENTED` أو `TESTED جزئيًا`، وليس `VERIFIED`.
