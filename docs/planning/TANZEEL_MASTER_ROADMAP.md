## 1. المبادئ الحاكمة

1. **الموثوقية قبل عدد الميزات:** لا تُضاف ميزة إذا كسرت الاستقرار أو وسّعت سطح الهجوم دون ضوابط.
2. **التنزيل الأساسي لا يعتمد على AI:** أي مساعد ذكي اختياري، ولا يجوز أن يصبح شرطًا لتنزيل ملف.
3. **كل مرحلة قابلة للاختبار مستقلة:** لكل مرحلة هدف ونطاق واختبارات ومخرج ومخاطر وبوابة خروج.
4. **لا شبكة حقيقية في CI:** خوادم وهمية، ساعة وهمية، عينات مسجلة، وبيانات تركيبية.
5. **الواجهة لا تلمس الملفات ولا الشبكة:** كل عملية حساسة تمر عبر أوامر Tauri محددة.
6. **العربية أولًا:** العربية RTL هي الافتراضي، والإنجليزية LTR خيار فوري، والتكافؤ 100% في المفاتيح.
7. **الأسرار لا تدخل المستودع:** لا كلمات مرور، ولا مفاتيح، ولا شهادات، ولا cookies في السجلات أو الاختبارات.
8. **الحدود القانونية صريحة:** لا DRM، ولا تجاوز حماية، ولا محتوى مدفوع أو خاص دون حق، ولا زحف خارج النطاق.
9. **البناء لا يساوي القبول:** نجاح `cargo build` أو `pnpm build` لا يثبت أن ميزة تعمل.
10. **القرارات غير المحسومة تبقى مفتوحة:** تُسجل في [OPEN_DECISIONS.md](OPEN_DECISIONS.md) ولا تُحسم ضمنيًا.

### 1.1 معاني الحالات

| الحالة | المعنى |
| --- | --- |
| `DESIGNED` | يوجد تصميم أو عقد مكتوب، ولا يوجد كود إنتاجي. |
| `IMPLEMENTED` | يوجد كود أو إعداد في المستودع. |
| `CONNECTED` | المكوّن موصول بمكوّن آخر عبر واجهة محددة. |
| `EXECUTED` | شُغّل المكوّن فعليًا في بيئة تشغيل. |
| `TESTED` | يوجد اختبار آلي أو يدوي شُغّل، وله نتيجة مسجلة. |
| `VERIFIED` | يوجد دليل قابل لإعادة الإنتاج يثبت السلوك المطلوب، لا مجرد نجاح بناء. |
| `BLOCKED` | العمل متوقف لسبب مكتوب. |
| `NOT IMPLEMENTED` | لا يوجد تنفيذ. |
| `OPEN DECISION` | قرار يحتاج موافقة المالك قبل التنفيذ. |

### 1.2 قاعدة بوابة المرحلة

لا تبدأ مرحلة تنفيذ جديدة قبل تحقق كل ما يلي:

- Issue مستقل يحدد الهدف والنطاق ومعايير القبول وخارج النطاق.
- اعتماد المالك لمخرجات المرحلة السابقة، لا لمجرد نجاح البناء.
- نجاح كل اختبارات CI المطلوبة على Windows وLinux وmacOS.
- توثيق ما ثبت، ووسم ما لم يُختبر.
- تحديث الوثائق والقرارات المتأثرة، بما في ذلك ADR جديد إن لزم.
- خطة تراجع للمخاطر العالية.

## 4. المرحلة 1 — أساس التطبيق

| الحقل | القيمة |
| --- | --- |
| الحالة | `IMPLEMENTED + TESTED` محليًا؛ `VERIFIED` جزئيًا فقط |
| الاعتماد | المرحلة 0 |
| النطاق | Tauri/React shell، تنقل، i18n/RTL، مظهر، إعدادات، SQLite، أخطاء أساسية، وصول أساسي |

**الهدف:** تطبيق ويندوز يفتح، يعرض واجهة عربية RTL، يبدّل إلى الإنجليزية فورًا، ويحفظ إعدادات أساسية، دون أي تنزيل أو اتصال شبكة.

**الميزات المطلوبة:**

- هيكل Tauri 2 + React 19 + TypeScript + Vite.
- نواة Rust typed للإعدادات والتحقق.
- شاشات: الرئيسية، الإعدادات، حول.
- i18n: `ar` و`en`، تبديل فوري، `dir` و`lang` على الجذر.
- CSS بخصائص منطقية، وتخطيط RTL/LTR من ملف واحد.
- إعدادات: اللغة، المظهر، مجلد التنزيل.
- SQLite مع ترحيل أولي، وجدول إعدادات بصف واحد.
- بديل localStorage للتشغيل خارج Tauri للاختبارات فقط.
- أخطاء تحميل/حفظ أساسية، ورسائل واضحة.
- تسميات وصول، `aria-current`، `role="status"`، `role="alert"`.

**الاعتمادات التقنية:** Tauri 2، React، TypeScript، i18next، rusqlite، Vite، Vitest، Testing Library.

**المخرجات المتوقعة:**

- `apps/desktop` و`apps/desktop/src-tauri`.
- `crates/tanzeel-core` و`crates/tanzeel-storage`.
- ترحيل `0001_settings.sql`.
- اختبارات وحدة وواجهة، ولقطات RTL/LTR.
- CI حقيقي يبني ويختبر.

**الاختبارات الآلية الموجودة:**

- 18 اختبار JS: تكافؤ المفاتيح، منع النصوص الصلبة، CSS منطقي، تبديل اللغة، الإعدادات، منع الشبكة.
- 17 اختبار Rust: 9 للنواة و8 للتخزين.
- نجاح lint وtypecheck وbuild و`cargo fmt` و`clippy` محليًا.

**الفجوات قبل `VERIFIED`:**

- لم تُشغّل نافذة Tauri بصريًا ضمن هذه المراجعة.
- لم يُختبر حفظ SQLite عبر أمر Tauri من داخل التطبيق الفعلي.
- لم تُختبر لقطات RTL/LTR بصريًا في هذه المراجعة.
- لا اختبار E2E، ولا اختبار وصول آلي، ولا اختبار نص طويل/جمع عربي.
- لا اختبار لمسار فشل حفظ اللغة من زر الترويسة.

**الاختبارات اليدوية المطلوبة:**

- فتح التطبيق على Windows 10 22H2 وWindows 11 نظيفين.
- تبديل اللغة من الترويسة ومن الإعدادات، وإعادة تشغيل التطبيق.
- حفظ مجلد تنزيل صالح، ورفض مسار نسبي، وإعادة التشغيل.
- تبديل المظهر فاتح/داكن/حسب النظام.
- التنقل بلوحة المفاتيح وقراءة التسميات بقارئ شاشة.
- لقطات RTL وLTR للشاشات الثلاث.

**سيناريوهات الفشل:**

- قاعدة بيانات تالفة أو غير قابلة للفتح.
- مجلد بيانات غير قابل للكتابة.
- إعدادات محفوظة بمخطط قديم أو قيم غير معروفة.
- فشل حفظ اللغة من الترويسة دون إبلاغ المستخدم.
- تبديل لغة سريع أثناء تحميل الإعدادات.
- نص عربي طويل يكسر التخطيط.

**الأمان:** CSP محلي، لا موارد بعيدة، لا وصول مباشر من الواجهة للملفات/الشبكة، تحقق مزدوج في Rust، لا أسرار.

**الأداء:** هدف مبدئي لبدء أقل من 3 ثوانٍ وذاكرة خمول أقل من 200MB، **لم يُختبر**. لا تُعلن هذه الأرقام كضمان.

**خارج النطاق:** أي تنزيل، طابور، يوتيوب، إشعارات، tray، تحديثات، مثبّت نهائي.

**معايير الخروج:**

- كل اختبارات JS/Rust تنجح على الأنظمة الثلاثة.
- تشغيل نافذة Tauri فعليًا على Windows موثق.
- حفظ/قراءة SQLite عبر Tauri موثقان.
- RTL/LTR ولقطات الشاشات الرئيسية موثقة بصريًا.
- لا طلبات شبكة، ولا أسرار، ولا نصوص صلبة، وتكافؤ 100%.
- مراجعة المالك واعتماد الدمج.

**الدليل المطلوب:** أوامر الاختبار ونتائجها، لقطات RTL/LTR، سجل تشغيل Tauri، مسار قاعدة البيانات، ومراجعة المالك.

**المخاطر والتخفيف:**

| المخاطرة | التخفيف |
| --- | --- |
| اختبارات jsdom لا تثبت سلوك Tauri | اختبار تكامل Tauri + تشغيل يدوي موثق |
| اختلاف تحقق الواجهة عن Rust | عقد واحد ومصدر حقيقة واحد للتحقق |
| localStorage يخفي فشل SQLite | منع fallback في الإنتاج أو الإبلاغ عنه بوضوح |
| لقطات ثابتة لا تكفي | فحص بصري + اختبار E2E لاحقًا |

## 5. المرحلة 2 — محرك HTTP/HTTPS الأساسي

| الحقل | القيمة |
| --- | --- |
| الحالة | `DESIGNED` / `NOT IMPLEMENTED` |
| الاعتماد | المرحلة 1، واعتماد قرار محرك HTTP |
| النطاق | تنزيل مباشر، اتصال واحد ومتعدد، استئناف، إلغاء، تقدم، إعادة محاولة |

**الهدف:** تنزيل ملف `HTTP/HTTPS` موثوق، مع تقدم واستئناف وإلغاء وإعادة محاولة، وتسريع اختياري فقط عندما يسمح الخادم.

**الميزات المطلوبة:**

- محمّل HTTP في Rust داخل `tanzeel-download`، لا في الواجهة.
- تحقق كامل من الرابط: `http/https` فقط، الطول، الترميز، إعادة التوجيه، العناوين الخاصة.
- `HEAD` أو `GET` بنطاق صغير لاكتشاف `Accept-Ranges` و`Content-Length` و`ETag`/`Last-Modified`.
- تنزيل اتصال واحد كمسار أساسي مضمون.
- تنزيل متعدد الأجزاء فقط عند `Range` و`206` و`Content-Length` صالح.
- ملفات مؤقتة `.part` وأجزاء مستقلة، ثم دمج وإعادة تسمية ذرية.
- استئناف بعد الانقطاع، مع التحقق من ثبات الملف.
- إيقاف مؤقت واستئناف وإلغاء آمن.
- تقدم، سرعة، ETA، عدد الأجزاء النشطة.
- إعادة محاولة للأخطاء العابرة، وتباعد متزايد، وحد أقصى.
- مهلات اتصال وقراءة، وحد لحجم الاستجابة والتحويلات.
- تعامل مع `404` و`500` و`429` و`503` و`Retry-After`.
- تعامل مع خادم لا يدعم `Range` أو يعيد بيانات ناقصة/خاطئة.
- تعامل مع ملف 0 بايت، وملف ضخم، واسم بلا امتداد، و`Content-Disposition`.
- ترويسات مخصصة و`Referer` عند الحاجة، دون تسريب.
- دعم cookies/auth **فقط** وفق قرار الأمان والخصوصية المعتمد، وليس افتراضيًا.
- حد للتزامن الكلي وللمضيف، ومنع إغراق الخادم.
- إلغاء سريع ينظف المؤقتات أو يتركها قابلة للاستئناف وفق سياسة معلنة.
- أحداث تقدم مخففة (2/ثانية) لا تغرق الواجهة.
- خادم HTTP وهمي للاختبار، لا شبكة حقيقية في CI.

**الاعتمادات التقنية:** `tanzeel-download`، `tanzeel-core` لنموذج المهمة، `tanzeel-storage` لحالة الأجزاء، محرك وقت تشغيل غير متزامن (قرار مفتوح)، مكتبة HTTP (قرار مفتوح).

**المخرجات المتوقعة:**

- crate المحرك، واجهة `DownloadEngine`، ونموذج أجزاء.
- خادم اختبار محلي يدعم `Range` و`206` و`429` والانقطاع.
- أوامر/أحداث Tauri للبدء والإيقاف والاستئناف والإلغاء.
- توثيق سلوك الاستئناف والفشل.

**الاختبارات الآلية المطلوبة:**

- `download_success` مع بصمة مطابقة.
- `download_resume_after_interruption` عند دعم `Range`.
- `download_restart_when_no_range` دون تلف.
- `download_cancel_cleans_partial` أو يترك حالة قابلة للاستئناف بوضوح.
- `download_404_returns_not_found` و`download_500_retries`.
- `download_timeout_is_bounded`.
- `redirect_to_file_scheme_rejected` و`redirect_limit_enforced`.
- `private_ip_rejected_by_default`.
- `content_length_missing_falls_back_to_single`.
- `segmented_download_matches_hash`.
- `segments_resume_after_restart`.
- `etag_change_restarts_safely`.
- `server_without_range_falls_back`.
- `per_host_and_global_limits_respected`.
- `429_backs_off_segments` مع `Retry-After`.
- `zero_byte_file_is_valid`.
- `content_disposition_filename_is_sanitized`.
- `progress_events_are_throttled`.
- `cancel_during_segment_merge_is_safe`.
- `disk_full_is_reported_without_corruption` (محاكاة).

**الاختبارات اليدوية:**

- تنزيل ملف صغير ومتوسط وكبير من خادم محلي مضبوط.
- قطع الاتصال في منتصف التنزيل ثم الاستئناف.
- خادم يرفض `Range`، وخادم يعيد `429`.
- إلغاء أثناء التنزيل، والتحقق من عدم بقاء ملفات مؤقتة غير مفسرة.
- قياس السرعة والذاكرة على جهاز مرجعي، دون ادعاء تسريع مضمون.

**سيناريوهات الفشل:**

- خادم يعيد `206` بمدى خاطئ أو `Content-Length` متناقض.
- تغيّر الملف على الخادم أثناء التنزيل.
- انقطاع جزء واحد فقط.
- قرص ممتلئ أو صلاحية كتابة مفقودة.
- مسار نهائي خارج مجلد التنزيل.
- اسم ملف محجوز أو طويل أو يحتوي محارف تحكم.
- خادم يعيد HTML بدل الملف.
- إعادة توجيه إلى شبكة محلية أو مخطط غير مسموح.
- إلغاء متزامن مع الدمج أو إعادة التسمية.

**الأمان:** منع SSRF، منع path traversal، منع حقن الترويسات، عدم تسجيل cookies أو رموز، حدود حجم ومهلة، عدم اتباع تحويلات خطرة، وعدم الثقة بـ`Content-Disposition` أو `Content-Type`.

**الأداء:** تحديث تقدم مخفف، ذاكرة محدودة لكل جزء، عدم تحميل الملف كاملًا في الذاكرة، قياس الأثر الفعلي للتسريع؛ لا وعود بنسبة سرعة.

**خارج النطاق:** الطابور متعدد المهام، الجدولة، الفيديو، المتصفح، الواجهة النهائية، استعادة ما بعد الانهيار على مستوى المهمة (المرحلة 3/4).

**معايير الخروج:**

- كل اختبارات المحرك تنجح على الأنظمة الثلاثة بلا شبكة حقيقية.
- ملفات الاختبار تطابق البصمة بعد التنزيل العادي والمجزأ.
- الاستئناف والتراجع عند غياب `Range` مثبتان.
- الإلغاء لا يترك ملفًا نهائيًا تالفًا.
- الحدود الأمنية مغطاة باختبارات.
- مراجعة بشرية وتوثيق كامل.

**الدليل المطلوب:** تقرير اختبارات الخادم الوهمي، بصمات الملفات، سجلات الاستئناف، وقياسات أداء أولية.

**المخاطر والتخفيف:**

| المخاطرة | التخفيف |
| --- | --- |
| تعقيد الأجزاء والاستئناف | حالة جزء واضحة، تحقق قبل الدمج، اختبارات انقطاع |
| خوادم ترفض التزامن | تراجع تلقائي وحدود لكل مضيف |
| هشاشة اختبارات الوقت | ساعة وهمية ومهلات قابلة للحقن |
| ادعاء تسريع غير مثبت | قياس محلي فقط، وإعلان النتائج لا الوعود |

## 6. المرحلة 3 — الموثوقية والسلامة وإدارة الملفات

- فتح الملف وفتح المجلد عبر platform layer.
- أسماء ملفات عربية وUnicode، وتطبيع معقول.
- منع المسارات الخبيثة، والأسماء المحجوزة، والمسارات الطويلة، ونقاط إعادة التحليل.
- أخطاء ملفات واضحة: قرص ممتلئ، صلاحية، مسار غير موجود، ملف مقفل.

**الاعتمادات التقنية:** المرحلة 2، `tanzeel-platform`، `tanzeel-storage`.

**المخرجات المتوقعة:**

- مدير ملفات ومسارات، وسياسة أسماء، وطبقة أخطاء ملفات.
- اختبارات نظام ملفات مؤقتة، ومحاكاة قرص ممتلئ.
- توثيق سياسة التنظيف والاستعادة.

**الاختبارات الآلية:**

- `delete_history_does_not_delete_file`.
- `delete_file_requires_explicit_confirmation`.
- `open_folder_uses_canonical_path`.

**الاختبارات اليدوية:**

- تنزيل باسم عربي واسم Unicode واسم محجوز.
- إغلاق التطبيق أثناء الكتابة ثم إعادة الفتح.
- محاكاة قرص ممتلئ أو مجلد للقراءة فقط.
- ملف موجود مسبقًا، واختيار الاستبدال/إعادة التسمية/التخطي.
- فتح الملف والمجلد من الواجهة.
- التأكد من عدم حذف ملفات المستخدم عند حذف السجل.

**سيناريوهات الفشل:**

- انقطاع كهرباء أو إنهاء عملية أثناء إعادة التسمية.
- ملف مؤقت موجود من محاولة سابقة.
- اسم ملف يختلف في التطبيع Unicode بين الأنظمة.
- مسار UNC أو شبكة غير متاحة.
- ملف مقفل بواسطة برنامج آخر.
- تعارض اسم مع مجلد.
- مساحة حرة كافية نظريًا لكنها نفدت أثناء الكتابة.

**الأمان:** منع الهروب من مجلد التنزيل، عدم اتباع نقاط إعادة التحليل، عدم تنفيذ الملف، عدم كشف المسارات الكاملة في السجلات، وحذف آمن قابل للتراجع حيث أمكن.

**الأداء:** عدم نسخ الملف كاملًا للتحقق إن أمكن، حساب بصمة متدفق، وتنظيف مؤقت لا يعطل البدء.

**خارج النطاق:** جدولة المهام (المرحلة 4)، معالجة الفيديو (5/6)، إدارة سلة المحذوفات على مستوى النظام (قرار لاحق).

**معايير الخروج:**

- لا فقدان لملف مكتمل أو تلف صامت في كل سيناريوهات الاختبار.
- كل ملف مكتمل يمر بتحقق حجم/بصمة.
- التعارضات لا تدهس ملفًا موجودًا.
- الاستعادة والتنظيف موثقان ومختبران.
- أسماء عربية وUnicode تعمل على Windows.

**الدليل المطلوب:** سجلات اختبار الاستعادة، بصمات الملفات، لقطات تعارض الأسماء، وتقرير أخطاء الملفات.

**المخاطر والتخفيف:**

| المخاطرة | التخفيف |
| --- | --- |
| تلف عند إعادة التسمية | نفس وحدة التخزين، إعادة تسمية ذرية، تحقق قبلها |

## 8. المرحلة 5 — محرك الفيديو

| الحقل | القيمة |
| --- | --- |
| الحالة | `DESIGNED` / `NOT IMPLEMENTED` |
| الاعتماد | المرحلة 4، واعتماد قرار محرك الفيديو (ADR-0004 مفتوح) |
| النطاق | مصدر واحد، بيانات وصفية، جودات، تنزيل فعلي، دمج عند الحاجة |

**الهدف:** تنزيل فيديو عام واحد من مصدر مدعوم، مع عرض الصيغ الفعلية واختيار المستخدم، وإثبات يدوي على Windows.

**الميزات المطلوبة:**

- محوّل مصدر واحد فقط في البداية، لا وعود بتوافق عالمي.
- استخراج URL والبيانات الوصفية: العنوان، المدة، الصيغ، الجودات، الحجم التقريبي.
- اختيار الجودة/الصيغة من المتاح فقط.
- تنزيل فيديو + صوت أو فيديو فقط أو صوت فقط حسب التوفر.
- دمج عبر `ffmpeg` عند الحاجة، مع التحقق من البصمة والإصدار.
- تقدم التنزيل والدمج، وإلغاء آمن.
- تصنيف الأخطاء: خاص، محذوف، محظور، DRM، غير مدعوم، رابط منتهٍ.
- معالجة انتهاء صلاحية URL وإعادة التحليل عند الحاجة.
- دعم cookies/auth فقط بقرار أمني صريح.
- عزل العملية الخارجية: وسائط مصفوفة، بلا shell، مهلة، حد مخرجات، قتل شجرة العمليات.
- اختبارات بمخرجات مسجلة أو عملية وهمية، لا شبكة حقيقية في CI.
- اختبار يدوي موثق لفيديو عام.

**الاعتمادات التقنية:** `tanzeel-download`، محوّل المحرك، `ffmpeg`، قرار الترخيص والتوزيع، قرار ADR-0004.

**المخرجات المتوقعة:**

- محوّل مصدر واحد، مخطط بيانات وصفية، وأخطاء مصنفة.
- إدارة sidecar/عملية فرعية موقعة أو متحقق من بصمتها.
- اختبارات fixtures، وتوثيق الحدود.

**الاختبارات الآلية:**

- `video_metadata_fixture_parses`.
- `format_selection_respects_user_choice`.
- `invalid_format_is_rejected`.
- `video_plus_audio_merge_calls_ffmpeg` بعملية وهمية.
- `merge_failure_keeps_source`.
- `private_video_error_is_actionable`.
- `drm_error_is_refused`.
- `expired_url_is_reported`.
- `cancel_kills_process_tree`.
- `engine_output_is_treated_as_untrusted`.
- `no_live_network_in_ci`.

**الاختبارات اليدوية:**

- فيديو عام واحد على Windows 10 أو 11، بجودة مختارة.
- فيديو يحتاج دمجًا، وآخر لا يحتاجه.
- فيديو خاص/محذوف/DRM للتأكد من الرسالة والرفض.
- إلغاء أثناء التنزيل وأثناء الدمج.
- التحقق من عدم تشغيل الملف تلقائيًا.

**سيناريوهات الفشل:**

- تغيّر الموقع وكسر الاستخراج.
- رابط منتهي أو محمي.
- فشل `ffmpeg` أو نقص مساحة.
- مخرجات ضخمة أو غير متوقعة.
- إلغاء أثناء العملية الفرعية.
- محتوى يتطلب تسجيل دخول.

- الصيغ المعروضة هي المتاحة فقط.
- الفشل مصنف وقابل للفهم.
- لا DRM ولا محتوى خاص في الاختبارات.
- المحرك معزول وآمن.

**الدليل المطلوب:** سجل الاختبار اليدوي، لقطة/ملف ناتج، بيانات وصفية، وسجل عملية `ffmpeg` الوهمية.

**المخاطر والتخفيف:**

## 10. المرحلة 7 — استخراج روابط الموقع

**الهدف:** استخراج روابط نوع معيّن من صفحة واحدة بمعاينة وتأكيد، دون زحف واسع أو تجاوز حدود الموقع.

**الميزات المطلوبة:**

- إدخال رابط صفحة `http/https` واحد.
- جلب HTML ثابت فقط، دون JavaScript.
- نطاق أصلي واحد، عمق 1، صفحة واحدة، حد روابط افتراضي 200.
- احترام `robots.txt`، حد معدل، `User-Agent` واضح.
- منع العناوين الخاصة والمحلية والتحويلات الخطرة.
- استخراج حسب نوع الملف/الامتداد أو `Content-Type` بعد التحقق.
- إزالة التكرار، وتنقية الروابط، ورفض غير الصالح.
- معاينة النتائج والنوع والحجم إن توفر.
- لا تنزيل قبل اختيار وتأكيد المستخدم.
- إلغاء آمن دون آثار.
- حدود حجم الصفحة وعدد الروابط.

**الاعتمادات التقنية:** `tanzeel-capture`، محلّل HTML (قرار مفتوح)، خادم وهمي، نموذج المهمة.

**المخرجات المتوقعة:**

- زاحف محدود، مرشح أنواع، شاشة معاينة/تأكيد.
- اختبارات robots/SSRF/حدود.

**الاختبارات الآلية:**

- `crawl_extracts_matching_links`.
- `crawl_same_origin_only`.
- `crawl_respects_robots_disallow`.
- `crawl_enforces_max_links_and_size`.
- `crawl_blocks_private_ip_and_bad_redirect`.
- `crawl_no_javascript_execution`.
- `crawl_requires_confirmation_before_download`.
- `crawl_cancel_leaves_no_artifacts`.
- `crawl_duplicate_urls_removed`.
- `crawl_non_html_response_rejected`.

**الاختبارات اليدوية:**

- صفحة روابط PDF/MP4.
- صفحة فارغة، صفحة ضخمة، صفحة تتطلب JavaScript.
- موقع يمنع `robots.txt`.
- نطاق مختلف وتحويل إلى IP خاص.
- إلغاء أثناء السحب.

**سيناريوهات الفشل:**

- صفحة تتطلب JavaScript.
- `robots.txt` غير متاح.
- روابط مشفرة/مكررة.
- موقع بطيء أو يعيد HTML ضخمًا.
- تحويل إلى مخطط غير مسموح.
- محتوى خلف تسجيل دخول.

**الأمان:** منع SSRF، حدود حجم/معدل، عدم إعادة استخدام cookies، عدم تنفيذ JS، وعدم تجاوز paywall.

**الأداء:** صفحة واحدة، حد حجم، طلب واحد في الثانية افتراضيًا، لا ينافس التنزيلات.

**خارج النطاق:** الزحف متعدد الصفحات/النطاقات، المتصفح بلا واجهة، تسجيل الدخول، التنزيل التلقائي.

**معايير الخروج:**

- كل اختبارات الحدود والـSSRF تنجح.
- لا تنزيل قبل تأكيد.
- `robots.txt` مطبق.
- الصفحات غير المدعومة معلنة بوضوح.

**الدليل المطلوب:** سجلات خادم وهمي، نتائج robots، لقطات المعاينة، واختبار إلغاء.

**المخاطر والتخفيف:**

| المخاطرة | التخفيف |
| --- | --- |
| إساءة استخدام الزحف | صفحة واحدة، نطاق واحد، حدود، `robots.txt` |
| SSRF | منع العناوين الخاصة والتحويلات |
| هشاشة HTML | محلّل DOM لا regex، واختبارات عينات |
| مخاطر قانونية | توثيق الحدود ومراجعة قبل الإصدار |

**الاعتمادات التقنية:** مزود AI (قرار مفتوح)، طبقة خصوصية/تنقية، تكامل اختياري، اختبارات مزود وهمي.

**المخرجات المتوقعة إن اعتمدت:** عقد خدمة، سياسة بيانات، واجهة اختيارية، اختبارات.

**الاختبارات الآلية:**

- `ai_disabled_core_downloads_still_work`.
- `ai_requires_explicit_consent`.
- `ai_redacts_urls_headers_cookies`.
- `ai_timeout_falls_back_to_local_explanation`.
- `ai_provider_error_is_visible`.
- `ai_does_not_fabricate_diagnosis` (تقييم عينات/حدود).
- `ai_opt_out_removes_data`.

**الاختبارات اليدوية:**

- تعطيل AI والتنزيل.
- طلب تشخيص مع موافقة/رفض.
- فشل الشبكة.
- التحقق من عدم إرسال بيانات حساسة.

**سيناريوهات الفشل:**

- مزود غير متاح.
- استجابة مضللة.
- بيانات حساسة في الطلب.
- تكلفة/حد استخدام.
- تغيّر سياسة مزود.

**الأمان/الخصوصية:** لا بيانات افتراضية، موافقة لكل إرسال أو إعداد واضح، تنقية، تشفير، عدم تخزين، وسياسة احتفاظ.

**الأداء:** لا يعيق التنزيل، مهلة قصيرة، وعدم استدعاء تلقائي في الخلفية.

**خارج النطاق:** AI محلي ثقيل، تنفيذ إجراءات تلقائية، إرسال ملفات، تشخيص قاطع بلا بيانات.

**معايير الخروج إن اعتمدت:**

- كل اختبارات الموافقة والتنقية والفشل تنجح.
- التنزيل يعمل مع تعطيل AI.
- لا بيانات حساسة في السجلات.
- مراجعة خصوصية/قانونية.

**التوصية:** لا تجعل AI شرطًا لـ`v1.0.0`؛ اجعله إصدارًا لاحقًا أو ميزة اختيارية معطلة افتراضيًا بعد استقرار النواة. القرار للمالك في [OPEN_DECISIONS.md](OPEN_DECISIONS.md).

## 14. المرحلة 11 — الأمان والخصوصية

| النطاق | نموذج تهديد، تحقق، أسرار، شبكة، ملفات، تحديثات، خصوصية |

**الهدف:** تقليل سطح الهجوم عبر كل الطبقات، وإثبات الضوابط باختبارات لا بتصريحات.

**الميزات والضوابط المطلوبة:**

- نموذج تهديد محدث لكل مرحلة.
- تخزين آمن للإعدادات الحساسة، وDPAPI/Credential Manager للأسرار.
- لا أسرار في الكود/السجلات/الاختبارات.
- تحقق مركزي من URL والمخطط والطول والتحويلات.
- منع SSRF والعناوين الخاصة افتراضيًا.
- منع path traversal ونقاط إعادة التحليل.
- تنفيذ بلا shell، ووسائط مصفوفة، وحدود عمليات.
- جسر متصفح مقيد.
- زاحف محدود.
- تحديثات موقعة ومصدر رسمي.
- فحص تبعيات وSBOM وتراخيص.
- تنقية السجلات.
- ضوابط خصوصية: لا تتبع افتراضي، حذف كامل، تصدير/حذف.
- اختبار اختراق/مراجعة قبل الإصدار.

**الاعتمادات التقنية:** كل المكونات، وخصوصًا `tanzeel-platform` و`tanzeel-capture`.

**المخرجات المتوقعة:**

- threat model، سياسة أسرار، مصفوفة صلاحيات، اختبارات أمنية، تقرير مراجعة.

**الاختبارات الآلية:**

- `url_scheme_rejected`.
- `private_ip_rejected`.
- `redirect_to_file_rejected`.
- `path_traversal_rejected`.
- `symlink_escape_rejected`.
- `command_injection_impossible` (وسائط مصفوفة).
- `secret_scan_clean`.
- `update_rejects_bad_signature`.
- `log_redacts_tokens`.
- `native_message_rejects_unknown_sender`.
- `crawler_blocks_private_ip`.
- `dependency_vulnerability_gate`.
- `permissions_are_minimal`.

**الاختبارات اليدوية:**

- محاولة حقن مسار/أمر.
- رسالة متصفح مزيفة.
- رابط إلى localhost.
- تحديث بتوقيع خاطئ.
- حذف كل البيانات.
- مراجعة صلاحيات Windows.

**سيناريوهات الفشل:**

- سر مكشوف.
- تحديث مزيف.
- جسر متصفح مفتوح.
- زاحف يصل إلى شبكة محلية.
- سجل يحتوي token.
- تبعية حرجة.

**الأمان:** هو نطاق المرحلة نفسه؛ لا يُختصر بفحص واحد.

**الأداء:** التشفير/التحقق لا يسبب تجميدًا، وفحص التبعيات في CI لا يعطل كل PR بلا داع.

**خارج النطاق:** أمان مثالي مضمون، اختبار أنظمة الغير، DRM bypass.

**معايير الخروج:**

- threat model معتمد.
- لا ثغرات عالية/حرجة معروفة غير معالجة.
- كل ضوابط URL/ملف/عملية/تحديث مختبرة.
- مراجعة أمنية بشرية.
- خطة استجابة للحوادث.

**الدليل المطلوب:** تقرير ثغرات، سجلات اختبارات، threat model، ومراجعة.

**المخاطر:**

| المخاطرة | التخفيف |
| --- | --- |

| تعقيد الجسر | أقل صلاحيات، تحقق صارم |
| ثقة زائدة | اختبارات سلبية ومراجعة |

## 21. قواعد عامة لكل مرحلة

1. Issue أولًا، ثم فرع، ثم PR صغير واحد.
2. اختبارات الميزة وحالات الفشل في نفس PR.
3. CI أخضر على الأنظمة الثلاثة.
4. مراجعة بشرية وموافقة مالك.
5. لا دفع مباشر إلى `main`، ولا دمج باختبارات فاشلة.
6. لا أسرار، ولا مدخلات غير منقاة، ولا تنفيذ من نصوص.
7. الوثائق في نفس PR، وما لم يُختبر يوسم.
8. لا إصدار أو وسم دون موافقة.
9. لا تغيير نطاق أو اعتماد جديد دون قرار مالك.
10. كل ادعاء `VERIFIED` يحتاج دليلًا.

---

## 22. ما لا تفعله هذه الخارطة

- لا تنفذ أي مرحلة.
- لا تعتمد ADR مفتوحًا.
- لا تغيّر نطاق v1 المعتمد.
- لا تعلن أن أي ميزة مستقبلية تعمل.
- لا تستبدل وثائق PRD/ARCHITECTURE الحالية؛ هي مرجع تخطيطي إضافي حتى يعتمد المالك دمجها أو استبدالها.
