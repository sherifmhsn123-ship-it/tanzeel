## المرحلة 1 — الهيكل واللغة والإعدادات

**الهدف:** تطبيق يفتح، يعرض واجهة عربية RTL، ويبدّل للإنجليزية، ويحفظ إعدادات أساسية، دون أي تنزيل.

**يتضمن:**

- هيكل Tauri + React + TypeScript.
- نواة Rust بمخططات typed.
- شاشة رئيسية فارغة، شاشة إعدادات، شاشة «حول».
- i18n: `ar` و`en`، تبديل فوري، RTL/LTR.
- تخزين الإعدادات في SQLite مع أول ترحيل.
- تصميم مبدئي (ألوان، خط، مسافات) قابل للتبديل.
- اختبارات وحدة وواجهة.
- CI يفعّل مهام البناء والاختبار الحقيقية.

**شرط النجاح (اختبارات محددة):**

- [ ] `cargo test -p tanzeel-core` ينجح على الأنظمة الثلاثة.
- [ ] `cargo test -p tanzeel-storage` ينجح: ترحيل من قاعدة فارغة، قراءة/كتابة إعدادات، رفض قيمة غير صالحة.
- [ ] `pnpm test:i18n` يؤكد تكافؤ 100% بين `ar.json` و`en.json`.
- [ ] اختبار يمنع النصوص الصلبة في مكونات الواجهة.
- [ ] لقطات RTL/LTR للشاشات الرئيسية تنجح.
- [ ] اختبار تبديل اللغة دون إعادة تشغيل، مع بقاء الاختيار بعد إعادة التشغيل.
- [ ] `pnpm build` و`cargo build --workspace` ينجحان على الأنظمة الثلاثة.
- [ ] لا طلبات شبكة في هذه المرحلة (يُتحقق بمراقبة الاختبار).
- [ ] لا أسرار في قاعدة البيانات أو الملفات.

## قواعد الانتقال بين المراحل

1. **Issue أولًا:** لا عمل بدون Issue يحدد النطاق ومعايير القبول.
2. **فرع واحد لكل تغيير:** اسم واضح، مثل `phase-2/direct-download`.
3. **PR صغير:** يفعل شيئًا واحدًا، ويذكر البرومبت والاختبارات.
4. **CI أخضر على الأنظمة الثلاثة:** لا استثناءات.
5. **مراجعة بشرية:** المالك يراجع قبل الدمج.
6. **وثائق محدثة:** ما ثبت يُكتب، وما لم يُختبر يُوسم.
7. **لا دمج مباشر:** ممنوع الدفع إلى `main`.
8. **لا إصدار يدوي:** الإصدار من وسم على `main` عبر GitHub Actions.
