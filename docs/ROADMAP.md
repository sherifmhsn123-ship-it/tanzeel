## المرحلة 2 — الملفات المباشرة والتسريع

**الهدف:** تنزيل ملف `HTTP/HTTPS` موثوق، مع تقدم واستئناف وإلغاء وإعادة محاولة، وتسريع اختياري متعدد الأجزاء، دون أي منصة فيديو.

**يتضمن:**

- محمّل HTTP في Rust.
- تحقق كامل من الروابط.
- ملفات `.part` وإعادة تسمية ذرية.
- استئناف عبر `Range`.
- تقسيم الملف إلى أجزاء متوازية (ADR-0010)، مع حد كلي وحد لكل مضيف.
- التحقق من `ETag`/`Last-Modified` والحجم والبصمة بعد الدمج.
- التراجع إلى اتصال واحد عند غياب `Range` أو رفض الخادم.
- تقدم، سرعة، وقت متبقٍ، وعدد الأجزاء النشطة.
- إلغاء وتنظيف.
- إعادة محاولة للأخطاء العابرة.
- أسماء ملفات آمنة ومنع اجتياز المسار.
- اختبارات بخادم HTTP وهمي محلي.

**شرط النجاح (اختبارات محددة):**

## قواعد الانتقال بين المراحل

1. **Issue أولًا:** لا عمل بدون Issue يحدد النطاق ومعايير القبول.
2. **فرع واحد لكل تغيير:** اسم واضح، مثل `phase-2/direct-download`.
3. **PR صغير:** يفعل شيئًا واحدًا، ويذكر البرومبت والاختبارات.
4. **CI أخضر على الأنظمة الثلاثة:** لا استثناءات.
5. **مراجعة بشرية:** المالك يراجع قبل الدمج.
6. **وثائق محدثة:** ما ثبت يُكتب، وما لم يُختبر يُوسم.
7. **لا دمج مباشر:** ممنوع الدفع إلى `main`.
8. **لا إصدار يدوي:** الإصدار من وسم على `main` عبر GitHub Actions.
