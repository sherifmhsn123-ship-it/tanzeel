# ADR-0008: الأمان والخصوصية

- **الحالة:** مقترح — بانتظار موافقة المالك
- **التاريخ:** 2026-10-30
- **القرار:** نموذج الأمان والخصوصية
- **الوثائق المرتبطة:** [PRD](../PRD.md)، [ARCHITECTURE](../ARCHITECTURE.md)، [AGENTS](../../AGENTS.md)

## السياق

«تنزيل» يعالج:

- روابط وبيانات وصفية قادمة من الإنترنت (غير موثوقة).
- ملفات وسائط بأحجام وصيغ متنوعة.
- عمليات فرعية خارجية (`yt-dlp`، `ffmpeg`).
- مسارات ملفات يختارها المستخدم.
- تحديثات قادمة من الشبكة.
- اختياريًا: cookies ورموز تسجيل دخول.

أي خطأ في هذه الحدود قد يؤدي إلى:

- تنفيذ أوامر أو كتابة ملفات خارج المسار المسموح.
- تسريب رموز أو تاريخ تصفح.
- تثبيت تحديث مزيف.
- استنزاف القرص أو الذاكرة.
- تعريض المستخدم لمحتوى خبيث أو مطالبات قانونية.

## نموذج التهديد المختصر

| التهديد | المثال | التخفيف |
| --- | --- | --- |
| حقن أوامر | اسم ملف أو وسيط يحتوي `&` أو `;` | وسائط مصفوفة بلا shell؛ تحقق صارم |
| اجتياز مسار | اسم يحتوي `..\..\Windows` | تطبيع + `canonicalize` + منع الخروج |
| SSRF محلي | رابط يحوّل إلى `127.0.0.1` أو خدمة داخلية | حظر العناوين الخاصة افتراضيًا، تحقق من كل تحويل |
| بيانات وصفية خبيثة | عنوان يحتوي HTML/سكربت | عرض كنص، CSP، لا HTML غير موثوق |
| تحديث مزيف | بيان تحديث من خادم مخترق | توقيع بيان + HTTPS + تحقق بصمة |
| سرقة أسرار | cookies في سجل أو قاعدة بيانات | DPAPI/Credential Manager، تنقية السجلات |
| تبعية مخترقة | حزمة npm/Rust خبيثة | تثبيت إصدارات، lockfiles، مراجعة، فحص أمني |
| استنزاف موارد | ملف ضخم أو قائمة ضخمة | حدود، تحذير، مساحة قرص، مهلات |
| محتوى محمي | DRM/محتوى مدفوع | رفض واضح، لا تجاوز |
| إساءة استخدام | تنزيل غير قانوني | إخلاء مسؤولية، حدود، عدم ترويج |

## الخيارات

| الخيار | الإيجابيات | السلبيات | ملاءمة |
| --- | --- | --- | --- |
| **أمان افتراضي صارم + خيارات متقدمة صريحة** | يحمي المستخدم العادي؛ يسمح للمتقدم | قد يمنع بعض حالات الاستخدام | **مقترح** |
| أمان مرن بالكامل | لا قيود | سطح هجوم كبير؛ أخطاء كارثية | مرفوض |
| صندوق رملي كامل (VM/حاوية) | عزل قوي | ثقيل؛ تجربة مستخدم سيئة | ليس الآن |
| الاعتماد على مضاد الفيروسات | بسيط | لا يكفي؛ لا يغطي المنطق | مرفوض |

## القرار المقترح

### 1. لا أسرار في الكود

- لا كلمات مرور، مفاتيح API، رموز، أو شهادات في المستودع.
- `.gitignore` يمنع `.env` والشهادات.
- فحص أسرار آلي في CI.
- الأسرار في GitHub Secrets أو Windows Credential Manager فقط.
- أي سر يُكشف يُعتبر محروقًا ويُستبدل، لا يُحذف من التاريخ فقط.

### 2. تحقق من كل المدخلات

- الروابط: مخطط `http/https`، طول، ترميز، تحويلات، عناوين خاصة.
- البيانات الوصفية: حدود حجم، أنواع متوقعة، لا تنفيذ.
- أسماء الملفات: محارف ممنوعة، أسماء محجوزة، طول، مسار نهائي.
- الإعدادات: مخطط typed، قيم افتراضية آمنة.
- أوامر IPC: تحقق من النوع والصلاحية والحالة.

### 3. تنفيذ بلا shell

- العمليات الفرعية بوسائط مصفوفة.
- لا `cmd /c`، لا `powershell -Command` لبناء أوامر.
- `--ignore-config` و`--no-exec` حيث ينطبق.
- قتل شجرة العمليات عند الإلغاء.
- بيئة نظيفة، ومهلة، وحد لمخرجات.

### 4. عزل الواجهة

- WebView محلية فقط، CSP صارمة.
- لا وصول مباشر للملفات أو الشبكة.
- صلاحيات Tauri محدودة.
- لا تحميل موارد بعيدة داخل الواجهة.
- لا `innerHTML` لبيانات غير موثوقة.

### 5. الشبكة

- HTTPS مفضل، وHTTP مسموح فقط برغبة المستخدم مع تحذير.
- حظر `localhost` والشبكات الخاصة افتراضيًا.
- حد لإعادات التوجيه، ومنع التحويل إلى مخطط غير مسموح.
- مهلة اتصال وقراءة، وحد لحجم الاستجابة.
- عدم إرسال cookies إلا للمضيف المقصود.
- عدم تسجيل الاستعلامات الكاملة إذا احتوت رموزًا.

### 6. الأسرار وcookies

- لا cookies افتراضيًا.
- الاستيراد/الاستخدام بموافقة صريحة.
- تخزين مشفر عبر DPAPI/Credential Manager.
- لا تُسجَّل القيم.
- حذف فوري عند طلب المستخدم.

### 7. التحديثات

- توقيع بيان التحديث.
- رفض التوقيع الخاطئ.
- HTTPS فقط.
- لا تثبيت من مصدر غير GitHub Releases الرسمي.
- إمكانية تعطيل.

### 8. الخصوصية

- لا تحليلات، لا تتبّع، لا حساب في v1.
- لا إرسال بيانات إلا للروابط التي يطلبها المستخدم وفحص التحديث.
- سجلات محلية فقط، دوّارة، قابلة للحذف.
- حزمة تشخيص تُنشأ محليًا ولا تُرسل تلقائيًا.
- «حذف كل البيانات» واضح ومختبر.

### 9. التبعيات

- تثبيت الإصدارات وlockfiles.
- مراجعة أي تبعية جديدة: الترخيص، الصيانة، الشعبية، الأمان.
- فحص أمني آلي (Rust/Node) في CI.
- عدم إضافة تبعية لحل سطر واحد.

### 10. الإفصاح

- سياسة أمان في `SECURITY.md`.
- قناة إبلاغ خاصة قبل النشر العام.
- لا تُنشر تفاصيل ثغرة قبل إصلاحها.

## النتائج

- بعض الميزات (مثل تسجيل الدخول أو الشبكة المحلية) تحتاج موافقة وخيارًا متقدمًا.
- المستخدم العادي محمي افتراضيًا، والمتقدم يستطيع تجاوز بعض القيود بوعي.
- يجب اختبار الأمان كجزء من CI، لا مراجعة لاحقة.
- لا يمكن ضمان أمان كامل؛ الوثائق تصف ما تم اختباره فقط.

## قابلية التراجع

**منخفضة.** تخفيف الأمان لاحقًا ممكن، لكنه يزيد المخاطر. الأفضل بناء الحدود من البداية.

## ما يحتاج موافقة

- حظر الشبكة المحلية افتراضيًا.
- دعم cookies في v1 أم تأجيله.
- سياسة الاحتفاظ بالسجلات.
- هل نضيف فحص تحديثات تلقائيًا أم يدويًا.
- من مسؤول الإبلاغ الأمني؟
