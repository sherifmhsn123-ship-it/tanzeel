# ADR-0014: مكتبة HTTP لمحرك التنزيل المباشر

- **الحالة:** مقترح — بانتظار موافقة المالك
- **التاريخ:** 2026-11-06
- **القرار:** استخدام `reqwest` بوضع `blocking` مع `rustls` داخل حزمة `tanzeel-download`
- **الوثائق المرتبطة:** [PRD](../PRD.md)، [ARCHITECTURE](../ARCHITECTURE.md)، [ROADMAP](../ROADMAP.md)، [ADR-0004](0004-download-engine.md)، [ADR-0008](0008-security-privacy.md)، [ADR-0010](0010-segmented-downloads.md)

## السياق

تبدأ المرحلة 2 بمحرك تنزيل مباشر لملفات `HTTP/HTTPS`، ويحتاج المحرك إلى:

- TLS موثوق على ويندوز ولينكس وماك دون الاعتماد على OpenSSL في ويندوز.
- اتباع إعادة التوجيه مع رفض المخططات غير المسموحة والعناوين المحلية/الخاصة.
- بثّ الجسم إلى القرص مع `Range` و`If-Range`.
- فصل الاتصال عند الإلغاء، وحدود زمنية للاتصال.
- واجهة متزامنة تعمل داخل خيط عامل، بلا `async` معقّد في النواة.

القرارات `D-006` (محرك HTTP) و`ADR-0004` ما زالت «مقترحة»، لكن المرحلة 2 تحتاج مكتبة HTTP الآن. هذا الـADR يوثّق الخيار التنفيذي ولا يعتمد `ADR-0010` ولا أرقام التسريع.

## الخيارات

| الخيار | الإيجابيات | السلبيات | الملاءمة |
| --- | --- | --- | --- |
| **`reqwest` 0.13 blocking + `rustls`** | ناضج؛ TLS عبر `rustls`؛ بثّ `Read`؛ سياسة إعادة توجيه قابلة للتخصيص؛ موجود أصلًا في شجرة Tauri | يضيف `rustls` و`aws-lc`؛ زمن بناء أطول؛ سطح اعتماد أكبر | **مقترح** |
| `ureq` | أخف؛ واجهة متزامنة بسيطة | سياسة إعادة توجيه أقل مرونة؛ اعتماد جديد كامل | بديل |
| `hyper` مباشرة | تحكم كامل | تعقيد عالٍ؛ إعادة بناء إعادة التوجيه وTLS وإدارة الاتصال | غير عملي الآن |
| `aria2` كعملية فرعية | تسريع جاهز | عملية خارجية؛ سطح هجوم؛ لا يندمج مع إلغاء/تقدم النواة | مرفوض للمرحلة 2 |
| تنفيذ HTTP/1.1 يدويًا | لا اعتماد HTTP | هشاشة TLS/chunked/redirect؛ مخاطر أمنية | مرفوض |

## القرار المقترح

إضافة `reqwest = { version = "0.13", default-features = false, features = ["blocking", "rustls"] }` إلى `crates/tanzeel-download` فقط، مع:

- `no_proxy()` افتراضيًا في هذا الإصدار.
- `connect_timeout` قابل للضبط.
- `Accept-Encoding: identity` لمنع اختلاف الحجم عند الاستئناف.
- سياسة إعادة توجيه ترفض أي مخطط غير `http/https`، وأي اعتماد في الرابط، وأي تخفيض من `https` إلى `http`، وأي مضيف محلي/خاص ما لم يُفعّل الخيار المتقدم صراحة.
- يُحلّ اسم المضيف قبل الطلب ويُرفض إن أعاد أي عنوان محلي/خاص، ويُعاد الفحص لكل إعادة توجيه.
- لا shell، ولا تنفيذ أوامر، ولا كتابة خارج مجلد التنزيل.

## الأسباب

- `reqwest` يوفّر ما يحتاجه المحرك دون إعادة اختراع TLS أو إدارة الاتصال.
- `rustls` لا يعتمد على OpenSSL، وهو أنسب لتوزيع ويندوز.
- الواجهة المتزامنة تناسب خيط التنزيل وتسمح باختبارات محلية حتمية بلا runtime غير ضروري.
- سياسة إعادة التوجيه المخصصة تسمح بتطبيق قواعد `ADR-0008` قبل اتباع التحويل.
- الترخيص `MIT OR Apache-2.0` متوافق مع `GPL-3.0-or-later`.

## النتائج

- تزداد تبعيات البناء: `rustls`، `aws-lc-rs` (أو مزوّد TLS بديل)، و`hyper`/`tokio` الموجودة أصلًا.
- يجب مراقبة تحديثات `reqwest` و`rustls` أمنيًا.
- لا يعني هذا القرار اعتماد التسريع متعدد الأجزاء؛ `ADR-0010` يبقى «مقترحًا».
- لا دعم proxy أو cookies أو مصادقة في هذا الإصدار.
- اختبارات الخادم الوهمي تستخدم `127.0.0.1` مع سماح صريح في الاختبار فقط؛ الإنتاج يبقى مغلقًا افتراضيًا.

## قابلية التراجع

إزالة الاعتماد من `crates/tanzeel-download` وعزل المحرك خلف واجهة `download` الحالية. لا تغيير في قاعدة البيانات أو الواجهة في هذا الـPR.

## ما يحتاج موافقة

- اعتماد `reqwest` + `rustls` كمكتبة HTTP للمرحلة 2.
- تأكيد ترخيص `rustls` و`aws-lc-rs` ضمن مراجعة التراخيص النهائية.
- اعتماد `ADR-0010` وأرقامه قبل تنفيذ الأجزاء المتوازية.

## ما لم يُختبر

- الشبكة الحقيقية وTLS مع مواقع فعلية.
- macOS arm64.
- مقاومة DNS rebinding بعد تغيّر DNS بين التحقق والاتصال.
- استجابة تتوقف بعد الترويسات دون إغلاق: لا توجد مهلة قراءة منفصلة بعد بدء الجسم.
- proxy، cookies، مصادقة، و`Retry-After` بصيغة تاريخ.
- امتلاء القرص الحقيقي (اختبار التحويل موجود فقط).
